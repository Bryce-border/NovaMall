# NovaMall 简历项目经历

适用方向：Java 后端开发实习 / 校招。依据：2026-09-11 项目代码与已有验证记录。

## 推荐版：突出 Redis 与 RabbitMQ

### NovaMall 分布式商城后端 | Java 后端开发

**项目介绍：** 基于 Spring Cloud Alibaba 的商城后端实践项目，覆盖商品查询、SKU 下单、购物车结算及订单流转，并实现 Redis 缓存与秒杀预校验、RabbitMQ 异步处理和库存预占等机制，重点处理重复请求与跨服务协作。

**技术栈：** Spring Boot 3、Spring Cloud Alibaba、MyBatis-Plus、MySQL、Redis、RabbitMQ、OpenFeign、Nacos。

**核心工作：**

1. **Redis 商品缓存：** 针对商品重复查询，采用 Cache Aside 实现缓存读取、未命中回源和回填，设置随机 TTL 分散集中失效，并在 Redis 访问异常时回退 MySQL；通过 ZSet 累计浏览热度并提供热门商品查询。
2. **Lua 预校验与异步处理：** 将秒杀库存判断、用户去重和预扣操作整合为 Redis Lua 脚本，避免多条命令之间的并发竞争；校验通过后投递 RabbitMQ，由消费者执行数据库库存预占与秒杀记录落库，将请求受理与数据库处理分离。
3. **RabbitMQ 订单事件：** 基于本地 Outbox 将订单状态与事件共同提交，结合 Publisher Confirm、不可路由消息检查和退避重试发布订单事件；库存消费端通过预占状态迁移约束重复处理，并配置支付、取消事件的消费重试与死信队列。
4. **SKU 库存与交易快照：** 基于 MySQL 库存条件更新和版本号检查实现 SKU 预占、释放与确认；下单时服务端校价并保存商品规格、成交价和地址快照，避免不同规格混单及商品修改影响历史订单。
5. **购物车结算幂等：** 通过用户 ID 与请求键唯一约束，结合事务内锁行记录并复用原订单，处理成功请求的重复提交；同键更换收货地址时拒绝执行，明确重试与新购买的业务边界。
6. **版本化异步清理：** 将购物车清理任务与订单在同一事务中保存，后台通过 HTTP 调用用户服务按原版本条件删除，保护结算期间的用户修改，并支持清理失败后重试。

**可选补充：** 使用 JUnit 5、Mockito、MockMvc 覆盖库存、结算重试和失败处理；项目已有 69 项自动化测试在 OpenJDK 25 下通过，配置 JDK 17/25 CI 矩阵。

项目地址：https://github.com/Bryce-border/NovaMall

这版适合突出中间件应用和交易设计。简历空间有限时保留前五条，将第六条合并到第五条。Redis 秒杀是独立的受理与落库流程，普通订单支付、履约目前采用 Mock；面试展开时按实际边界说明。

## 交易主线版：突出订单与一致性设计

### NovaMall 商城交易后端 | Java 后端开发

**项目介绍：** 基于 Spring Cloud Alibaba 构建的商城后端实践项目，覆盖用户认证、商品查询、SKU 库存、购物车结算和订单状态流转，重点实现交易快照、重复请求处理与异步事件协作，支付和履约采用 Mock 流程。

**技术栈：** Spring Boot 3、Spring Cloud Alibaba、MyBatis-Plus、MySQL、Redis、RabbitMQ、OpenFeign、Nacos。

**核心工作：**

1. **SKU 建模与交易快照：** 将商品级下单解析为 SKU，按规格合并数量并由服务端查询当前价格；保存商品名称、规格、成交价及收货地址快照，避免不同规格混单及商品变更影响历史订单。
2. **库存预占与状态约束：** 基于 MySQL 库存条件更新和版本号检查实现 SKU 库存预占，通过预占记录唯一键及状态迁移处理重复释放、确认；结合订单条件更新约束支付、取消等操作的合法状态。
3. **购物车结算幂等：** 以用户 ID 与请求键建立唯一约束，结合事务内锁行处理同键并发请求，记录并复用已创建订单，避免成功请求重试重复下单；相同键更换收货地址时拒绝处理。
4. **订单事件可靠发布：** 将订单变更与 Outbox 事件在同一本地事务中写入，通过 RabbitMQ 发布确认、路由返回检查及退避重试衔接库存确认和释放，保留发送失败后的重试依据。
5. **购物车异步清理：** 将清理任务与订单共同提交，后台按购物车项 ID、用户 ID 和原版本执行条件删除；保护结算期间发生的数量或勾选变更，并支持远程清理失败后的重试。

**可选补充：** 使用 JUnit 5、Mockito、MockMvc 覆盖 SKU 合并、地址归属、结算重试、清理失败和入参校验；项目已有 69 项自动化测试在 OpenJDK 25 下通过，配置 JDK 17/25 CI 矩阵。

项目地址：https://github.com/Bryce-border/NovaMall

## 空间紧张时：四条精简版

**NovaMall 商城交易后端 | Java 后端开发**

**项目介绍：** 基于 Spring Cloud Alibaba 的商城后端实践项目，实现 SKU 下单、购物车结算、库存预占与 Mock 订单流转。

**技术栈：** Spring Boot、MyBatis-Plus、MySQL、Redis、RabbitMQ、OpenFeign、Nacos。

- **缓存与预校验：** 使用 Redis Cache Aside、随机 TTL 和 ZSet 支持商品缓存与热度排行；以 Lua 原子执行秒杀库存判断、用户去重与预扣。
- **消息异步处理：** 通过 RabbitMQ 消费完成秒杀预占和记录落库；普通订单采用 Outbox、发布确认、路由检查与退避重试衔接库存事件。
- **交易与库存：** 按 SKU 服务端校价并保存商品/地址快照，结合 MySQL 库存条件、版本号和预占状态迁移控制库存变化。
- **幂等与清理：** 利用用户与请求键唯一约束复用原订单；以持久化任务和版本条件删除实现购物车异步清理，保护后续修改。

## 为什么这样写

两份参考简历采用的共同结构是“项目是什么 + 关键技术 + 具体问题 + 实现机制 + 结果”。其中一份更偏向模块设计，另一份突出“针对某问题，使用某方案”的因果关系。

本稿采用相同表达方式，但结果来自本项目可以解释和检查的行为，不迁移参考简历中的性能比例。

| 本稿条目 | 希望面试官看到的能力 | 可展开的知识点 |
| --- | --- | --- |
| Redis 缓存 | 能根据访问特征组织缓存数据 | Cache Aside、TTL、回源、ZSet |
| Lua 与消息受理 | 能分离准入判断和后续处理 | 原子脚本、用户去重、异步结果、消息积压 |
| SKU 与快照 | 能从业务差异设计数据模型 | SPU/SKU、冗余与历史数据、BigDecimal、DTO |
| 库存控制 | 能分析并发写与状态转换 | 原子 UPDATE、乐观锁、行锁、本地事务 |
| 结算幂等 | 能处理重试与并发请求 | 唯一索引、请求语义、事务隔离、幂等键 |
| Outbox | 能识别数据库与消息双写问题 | 至少一次、确认机制、消费幂等、补偿 |
| 异步清理 | 能保护用户并发修改 | 最终一致性、版本条件、任务重试、ABA |

注册登录和基础 CRUD 放在简介中，不占据主要贡献条目。推荐版将 Redis、Lua 和 RabbitMQ 提升为主要贡献，采用实现机制和行为表达结果；当前未验证吞吐收益，秒杀也尚未接入完整普通订单生命周期，因此不添加性能数字或完整秒杀商城的表述。
